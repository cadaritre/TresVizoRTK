# Instrucciones para agentes

Estas reglas se aplican a todo el repositorio y deben leerse junto con la documentación pertinente antes de realizar cambios.

## Autoría y Git

- El propietario humano del repositorio debe ser la única identidad de autor y committer utilizada para los nuevos commits de su trabajo.
- Nunca atribuir al agente autoría, coautoría, mantenimiento ni contribución.
- Nunca agregar líneas `Co-authored-by` de agentes, modelos, bots o proveedores.
- Nunca agregar firmas o frases como `Generated by`, `Generated with`, `AI-assisted` o equivalentes en commits, pull requests, documentación o encabezados para atribuir el trabajo al agente.
- No agregar al agente a listas de autores o contribuidores.
- Conservar los avisos legítimos y las licencias de dependencias de terceros.
- No reescribir el historial existente para alterar atribuciones.
- No crear commits ni hacer push salvo solicitud expresa del propietario.
- Antes de cualquier commit autorizado, verificar la identidad Git efectiva del autor y del committer, así como el mensaje completo del commit.
- Usar la identidad Git real del propietario. No inventar su correo, usar cuentas del agente ni asumir que la identidad predeterminada del entorno le pertenece.
- Si falta la identidad del propietario o existe una discrepancia, preguntar antes de crear el commit.
- No modificar configuraciones globales de Git ni del agente.
- Si una integración añade atribución automáticamente y no puede evitarse mediante mecanismos soportados, informar antes de crear el commit. No inventar opciones de configuración.
- No realizar `amend`, `rebase`, `force-push` ni cambios destructivos sin autorización.

## Forma de trabajo

- Leer este archivo y la documentación pertinente antes de modificar el proyecto.
- Trabajar en cambios pequeños y enfocados en la tarea solicitada.
- No implementar etapas futuras por iniciativa propia ni sobreingenierizar el prototipo.
- No cambiar decisiones de hardware o arquitectura sin justificarlo.
- Preservar las modificaciones del usuario y evitar sobrescribir trabajo no relacionado.
- Mantener la documentación coherente con el estado real del proyecto.
- Escribir documentación y explicaciones en español; usar inglés para nombres de archivos y futuros identificadores técnicos.
- No afirmar que algo compila, funciona, está validado o cumple una precisión si no se comprobó.
- Indicar las pruebas realizadas y las que quedaron pendientes.
- No subir credenciales, registros privados ni datos de clientes.

## Reglas técnicas

- Verificar manuales del fabricante antes de fijar comandos, interfaces, niveles eléctricos, pinouts o tasas.
- Distinguir las especificaciones de un módulo de las conexiones y circuitos de su placa carrier.
- No asumir que un algoritmo sencillo de orientación equivale a una fusión GNSS/IMU validada para topografía.
- No asumir que la dirección de desplazamiento GNSS coincide con la dirección hacia la que apunta la carcasa.
- Mantener explícitas las unidades, los marcos de coordenadas, la referencia de altura y los tiempos de medición.
- Distinguir el instante de medición del instante de llegada de un mensaje por UART.
- Validar las latencias antes de depender de PPS o de señales de datos listos para sincronización.
- Tratar la calibración mecánica y la inicialización dinámica como asuntos distintos.
- No presentar el estado FIX como garantía suficiente de exactitud.
- No prometer 2 cm de precisión ni rendimiento bajo árboles sin ensayos independientes.
- No confundir el registro de observaciones para PPK con la ejecución del postproceso en el ESP32.
- No imponer el formato UBX al UM980; verificar su formato nativo y cualquier conversión necesaria.
- Diseñar considerando desconexiones, pérdida de correcciones, archivos incompletos y cierre seguro de la microSD.

## Alcance de la inicialización

La tarea inicial del repositorio solo permite estructura, documentación y metadatos. Esta limitación pertenece a esa tarea concreta: no impide implementar funciones en solicitudes futuras expresas, siempre que se respete el estado real y las reglas anteriores.
